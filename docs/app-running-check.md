# 判断阅读器是否正在运行

**不要用 `tasklist` / 任务管理器里的进程条目判断。** Windows 在一个进程已经退出、但仍有别的进程持有它的句柄时，会让 `tasklist` 继续列出该条目。这种僵尸条目 **0 线程、0 句柄、没有可执行路径**，看起来像「软件没关」，实际早已退出，不锁任何文件；之前因此误判过多次（以为用户没关软件，迟迟不敢更新 `dist/Reader-win-x64`）。

统一用：

```bash
node scripts/app-status.cjs          # 正在运行 → 退出码 0；未运行 → 退出码 1
node scripts/app-status.cjs --json   # 给脚本/自动化用
```

判定规则：

- 只有 **线程数 > 0 且能读到可执行路径** 的 `Reader.exe` / 本仓库的 `electron.exe` 才算运行中。
- `http://127.0.0.1:9222/json/list` 有响应 → 开发实例在运行（打包版不开放该端口）。
- 0 线程 / 0 句柄的条目会在输出里列为「已忽略的僵尸进程」，不影响结论。
- 这些僵尸条目是已退出的内核对象，重启后消失，不需要处理，也不能被 `Stop-Process` 删除。

关闭应用后（正常点 ×、老板键退出、或验收脚本 `window.close()`）再跑一次上面的命令确认。验收结束请用正常关闭，不要对应用 `Stop-Process -Force`。
