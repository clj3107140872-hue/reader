# 正文只渲染三章（2026-11-05）

## 起因

用户反馈：代码摸鱼模式拖动窗口会卡死（已用固定正文宽度修复一次），希望从根上降低重排量，像「起点读书」那样每次只渲染当前章、前一章、后一章，无论书多长，参与排版的字数都是一个量级。

## 做法

- 新增 `src/renderer/src/reader/chapterWindow.ts`：给定章节总数和当前章，返回 `[当前-1, 当前, 当前+1]` 的窗口（书首/书尾/短书自动收窄）。
- 卷轴模式只渲染窗口内的章节；滚到窗口首/尾时按新位置重新计算窗口，**一次滑一章**，工作量和书的总长度无关。
- 滑动会移除视口上方的一章，`scrollTop` 必须补回同样的高度，否则正文会跳。做法：`handleScroll` 在 `setCurrent` 前记录「滑动前后都在 DOM 里的那一章」的内容偏移（前进取新窗口起点，后退取当前窗口起点）；布局 effect 在重排后用同一章的偏移差修正 `scrollTop`。滚动容器设 `overflow-anchor: none`，避免浏览器自带的滚动锚定和这次修正叠加。
- `scrollToPosition`（目录/进度条/搜索/书签跳转）遇到目标章还没渲染时，按帧重试最多 8 次，等窗口重新居中后再定位到段落。
- 删除 `chapterSize.ts` 及 `content-visibility`/`contain-intrinsic-size`：只有三章时让它们完整排版，高度是精确值。之前的估算高度会让窗口滑动的偏移不准，出现「滑过去又被滑回来」的来回抖动。
- 翻页模式不变，仍然只渲染一章。

## 验证（离屏 `READER_ACCEPTANCE=1`，临时数据副本，不触碰真实 `data/`）

## 注意

滑动触发点由阅读位置探针决定：探针位于视口顶部下方 88 px（`currentPosition`），所以只有当新章正文到达这条线时窗口才滑动，不会在章标题刚露头时就抖动。验收时跨界的滚动量要大于 88 px，否则测不到滑动。
