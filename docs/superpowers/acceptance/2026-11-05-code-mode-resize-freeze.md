# 代码摸鱼模式拖动缩放卡死（2026-11-05）

## 现象

用户在代码注释（摸鱼）模式下拖动窗口边缘调整大小/位置，拖一会儿软件卡死。

## 根因

代码伪装里 `.reader-page` 是 `max-width: none`，窗口每变宽 1px，正文就要按新宽度重新折行。真实书 928 章、72,722 个段落：

| 操作 | 每步耗时 | 长任务 |
| --- | --- | --- |
| 只改高度 | 1–4 ms | 无 |
| 只改宽度（修复前） | 180–430 ms | 90–150 ms |
| 只改宽度（正文 `display:none`） | 1–4 ms | 无 |
| 只改宽度（只留 20 章 section） | 1–9 ms | 无 |

即卡顿完全来自整本书的重新排版。拖动时指针每移动一次就重排一次，任务越积越多，最终界面无响应。普通阅读模式没这个问题，是因为正文有 `max-width: 860px`，窗口变宽时正文宽度不变、不重排。

`currentPosition()` 里的 `document.elementsFromPoint` 在每次滚动事件中还会额外强制一次布局（约 26 ms），但不是主因：跳过整条滚动记录逻辑后，宽度拖动仍然是每步 90–150 ms。

## 修复

`Reader.tsx`：拖动边缘时（`window:resize-start` 会话）把正文宽度固定为当前的 `clientWidth`，松开指针时一次释放。

- `WindowResizeHandles` 增加 `onResizeSession` 回调，按下/结束（含指针捕获丢失）时通知阅读页；
- `ReaderBody` 在 `resizing` 为真时设置 `article.style.width = <当前宽度>px`，结束后移除。

拖动过程中正文宽度不变，不发生重排；松手后整本书按最终宽度重排一次。透明悬浮模式走同一套边缘把手，同样生效。
